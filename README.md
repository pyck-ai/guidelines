The engineering guidelines of the [pyck-ai](https://github.com/pyck-ai) organization, written once for people and coding agents alike.

## What is pyck-ai/guidelines?

Commits, issues, pull requests, READMEs, code reviews and CI pipelines follow the same rules in every pyck-ai repository. This repository holds those rules. The text is edited only in `docs/`. `AGENTS.md` points into it, and each skill carries a copy generated by `task generate`, so a skill folder works on its own. A person and an agent read the same sentence, and `task ci` fails on a stale copy.

Out of the box, pyck-ai/guidelines includes:

- **Guideline docs**: the rules for commits, issues, pull requests, READMEs, code review and CI, listed under [Documentation](#documentation).
- **AGENTS.md**: [the org-wide rules](./AGENTS.md) every agent follows, with a table that routes each task to its doc.
- **Skills**: one per doc under [`skills/`](./skills), each a short "when to use" plus a generated copy of the doc, and for `pull-requests` and `github-issues` of the org templates, for [opencode](https://opencode.ai) and pi. Claude Code is not a supported target.
- **AGENTS.md template**: [`templates/AGENTS.md`](./templates/AGENTS.md), the start of a repository's own `AGENTS.md`.
- **Skill generator**: [`scripts/generate-skills.sh`](./scripts/generate-skills.sh) writes each skill's copy of its doc and of the .github templates, with links rewritten to `~/.pyck/guidelines` paths; `task generate` runs it.
- **Template check**: [`scripts/check-templates.sh`](./scripts/check-templates.sh) fails when a doc or skill names a PR template heading or issue form that does not exist in pyck-ai/.github.

GitHub's own org defaults (issue forms, the PR template, the code of conduct, the security policy) stay in [pyck-ai/.github](https://github.com/pyck-ai/.github).

## Getting started

```sh
git clone git@github.com:pyck-ai/guidelines.git   # anywhere you keep checkouts
cd guidelines
less docs/git.md                                    # read the docs, start with git
task generate                                       # refresh the generated files under skills/ after editing docs/
task ci                                             # check docs and skills against pyck-ai/.github, the generated files for staleness, and the setup.sh tests
./setup.sh                                          # link ~/.pyck/guidelines and the skills into your home
./setup.sh uninstall                                # remove exactly what setup.sh made
```

`setup.sh` links files and configures no harness, so tell your harness to load the org rules. For opencode, add this to your `opencode.json` (opencode expands the leading `~/`):

```json
{ "instructions": ["~/.pyck/guidelines/AGENTS.md"] }
```

Earlier versions of `setup.sh` generated `~/.config/opencode/config.json` for this; `./setup.sh` and `./setup.sh uninstall` remove that file when it is still the generated one. If you want opencode to ask before agents edit the guidelines, set those `permission` rules in your own config.

Every repo with a `setup.sh` has its home at `~/.pyck/<repo>`, and `setup.sh` installs everything through it; clone there or let `setup.sh` link the checkout. Agent files name `~/.pyck/guidelines/...` paths and never URLs, because a fetched URL is text nobody reviewed.

`setup.sh` is tested on Linux and on WSL (run it inside the WSL home, not on the Windows drive). macOS is expected to work but is untested. Native Windows (Git Bash, PowerShell) is not supported, because `setup.sh` needs real symlinks.

Working on this repository needs [Task](https://taskfile.dev) and a checkout of [pyck-ai/.github](https://github.com/pyck-ai/.github) at `../.github`, or at the path in `PYCK_GITHUB_DIR`; nothing is fetched. Run `task --list` for every other command. `./setup.sh --dry-run` previews; behavior, conflicts and exit codes: the header of [`setup.sh`](setup.sh).
